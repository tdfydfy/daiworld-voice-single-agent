# Daiworld Voice 产品形态与共存边界

> 本文是产品架构边界，不是版本升级路线图。

## 1. 核心结论

Daiworld Voice 有两种长期并存的产品形态：

1. **主持人多 Agent 版**：最终、更高级、更完整的全能形态；
2. **单 Agent 版**：更直接、更简单的探索和聚焦形态。

两者面向不同场景，不能用“新版 / 旧版”“高级版替换简单版”来描述。

## 2. 四端矩阵

| 形态 | Web | HarmonyOS | 当前策略 |
|---|---|---|---|
| 主持人多 Agent | 外部产品形态，不在本仓库 | 外部产品形态，不在本仓库 | 本分支不包含 |
| 单 Agent | 当前 `/voice-native/`，分支 `native-open-source` | 待建立独立实现分支/形态 | 本仓库当前目标 |

## 3. 主持人多 Agent 版

### 3.1 产品定位

主持人是唯一的任务编排入口：

- 理解用户的跨领域意图；
- 选择一个或多个 Agent；
- 分配任务和顺序；
- 组织 Agent 互动；
- 维护共享上下文；
- 控制谁发言、谁继续工作；
- 向用户汇报流程和最终结果。

Agent 不需要一直监听用户，也不独立决定整个协作流程；它们服从主持人的任务安排，在自己的专业边界内完成工作。

### 3.2 适用场景

- 跨技术、内容、项目管理的复杂任务；
- 多 Agent 讨论、交叉审查和协作；
- 用户不想逐个点名和管理 Agent；
- 需要主持人维持全局上下文和发言秩序；
- 需要一个稳定的人机协作入口。

### 3.3 架构特点

- 常驻主持人控制面；
- 多 Agent Session；
- 主持人意图、任务、补充、切换、取消协议；
- 共享上下文桥接；
- 全局播放/发言权管理；
- 更完整的任务审计和跨 Agent 证据。

## 4. 单 Agent 版

### 4.1 产品定位

用户直接选择一个 Hermes Agent，与它持续对话：

- 用户自己听取回答；
- 用户自己决定何时补充、停止或切换 Profile；
- 当前 Agent 自己理解任务、调用工具并完成工作；
- 系统不增加主持人判断和多 Agent 编排。

### 4.2 适用场景

- 快速技术验证和协议实验；
- 只需要一个专业 Agent 的聚焦任务；
- 研究连续语音、全双工、审批、文件和历史等底层能力；
- 希望减少中间角色和交互复杂度；
- 为未来主持人版提炼可复用基础组件。

### 4.3 架构特点

- 一次只连接一个 Hermes Profile；
- Hermes 官方 Session 是唯一上下文；
- 非“停止”的语音默认成为下一轮输入；
- `queued:true` 处理补充；
- 语音层只负责听、播和展示；
- 不存在主持人或 Agent 间共享上下文。

## 5. 两种形态共享什么

可以共享的基础设施：

- HarmonyOS `AudioCapturer / AudioRenderer`；
- PCM16/16k 输入和 PCM16/24k 输出；
- WebSocket 二进制传输；
- 连接、重连、权限和后台生命周期；
- 消息列表、附件卡、历史侧栏等 UI 组件；
- 安全存储和公网 HTTPS/WSS；
- 回音消除、音频焦点和设备路由经验。

不能直接共享的核心控制逻辑：

| 领域 | 主持人版 | 单 Agent 版 |
|---|---|---|
| 会话所有者 | 主持人 + 多个 Agent | 当前选中的一个 Hermes Session |
| 用户输入解释 | 主持人意图和调度 | 普通下一轮；仅精确停止是控制 |
| 补充 | 主持人任务队列 | Hermes `queued:true` |
| Agent 切换 | 主持人编排和上下文桥接 | 用户手动切 Profile，独立 Session |
| 播放权 | 全局舞台麦克风/主持人管理 | 客户端 TTS 队列 |
| 历史 | 主持人任务和多 Agent 审计 | Hermes 官方 Session 历史 |
| 审批 | 可由主持人参与流程 | 直接响应 Hermes `approval.request` |

## 6. 研发分支规则

1. 主持人 Web 与主持人 HarmonyOS 暂不调整。
2. 单 Agent Native 当前发布基线为 `native-open-source`。
3. 单 Agent HarmonyOS 应从 Harmony 仓库新建独立分支，不在 `main` 上覆盖主持人协议。
4. 可抽取共享的音频、网络和 UI 基础模块，但不要让两种 Controller 共享同一套业务状态机。
5. 文档、测试和发布名称必须明确写出 `host` 或 `single-agent`，禁止只写“Voice最新版”。

## 7. 防止架构误合并

出现以下提议时应停止并重新确认：

- “单 Agent 已经稳定，所以删除主持人版”；
- “让单 Agent 客户端兼容 HOST 协议，顺便合成一个 Controller”；
- “主持人版直接改成 `prompt.submit` 就够了”；
- “两个产品共用一个历史数据库和一个播放状态”；
- “鸿蒙 main 直接切换到单 Agent 后端”。

正确做法是：共享底层组件，保持产品控制面独立。
