# 项目当前状态

更新时间：2026-08-17

- 总体状态：HarmonyOS `1.2.16 (1020016)` 已固定为当前发布版本；新应用图标、严格审批口令和无编号澄清语义已进入统一基线，自动化、ArkTS 类型检查、签名构建、覆盖安装和客观启动检查均完成。
- 当前发布基线：`1.2.16`，已取代 `1.2.14` 功能基线和 `1.2.15` 候选版本；桌面和启动窗口统一引用 `app_icon_v3`。
- 已完成能力：动态 Agent 与 Provider/模型身份同步、Session 恢复、连续 ASR、系统/远端 TTS、统一播放队列、消息重读、四类提示音、审批/澄清快速响应、停止任务、话筒路由切换、退出释放、有限音频恢复，以及实时/历史过程时间线。
- 过程时间线：实时事件和 Hermes 历史消息共用活动 reducer，支持稳定 ID、状态更新、活动级计时、单项展开、重复/迟到结果原地合并；历史详情失败时正文可回退，同时明确显示“历史过程未完整载入”。
- 当前策略：连续性协调器只维护后台 demand，真实音频组件自行持有 AudioSession；正文远端 PCM 保持通信流，短提示音经过统一 PlaybackQueue 和后台 ready 门后使用 `VOICE_ASSISTANT` 媒体流，避免蓝牙 SCO 冷启动吞掉整段短 PCM。
- `1.2.14` 变更：四条精确语音控制口令统一为共享策略；“退出软件”经幂等 `dispose()` 释放资源后结束 Ability；“停止任务”立即清理本地播放和挂起状态，并以请求代次和 Session 隔离重复请求、迟到回调、会话切换和新提问。远端请求只显示已确认、失败或待确认，不声称服务端队列已全部清空。
- `1.2.15` 变更：应用图标改为新的麦克风视觉并使用 `app_icon_v3` 规避桌面缓存；审批只接受整句“同意”或“取消”，允许 ASR 附加空格和标点但不接受“允许/拒绝/执行”等别名；澄清选项不编号，只将与已知选项语义文本一致的回复映射为规范值，数字、序号和未命中内容原样交给 Hermes。
- `1.2.16` 变更：审批归一化仅清理整句空格和口令两端标点，句中标点、夹带文字、近义词、数字及序号均不命中；澄清回复恢复完整收句窗口，不会把首个 ASR final 分段提前提交。
- 最近验证：Node `91/91`、Python既有基线 `37/37`、43 个 ETS 静态校验、ArkTS 类型检查、HAP 打包和签名均通过；签名 HAP SHA-256 为 `39FE0D32F3E347160ADF562AE65376424BF2C88E681E6B2A25C02597824A0430`，设备端版本和进程状态已确认。
- 当前待办：本版本无阻塞项；后续仅处理明确的新需求或真机回归。Hermes 全队列停止契约按用户决定降为非阻塞项，不再作为前端发布门。
