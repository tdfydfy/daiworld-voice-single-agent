# 动态 Agent 与语音回复优化

## 目标

- Agent 的数量、名称和公开信息由后端返回，客户端不再写死 Profile。
- 语音对话默认生成简洁、自然、适合播报的回答，同时保留代码、文件等完整屏幕内容。
- 顶部 Agent 区域更紧凑，并为每个 Agent 的角色形象预留稳定位置。

## 已确认决策

### 1. Agent Catalog

- Native Adapter 是 Agent 目录的权威来源，返回 `id`、`name`、`is_default` 和可选 `avatar_url`。
- 客户端只保存不透明的 Agent ID，不接收内部服务地址、凭据或其他部署信息。
- 移除后端固定 `PROFILES` 和鸿蒙端固定 `ProfileKey/ProfileInfo`；Agent 增删不再要求发布新版客户端。
- 已保存 Agent 不存在时自动回退到默认 Agent；没有可用 Agent 时显示明确的空状态。
- 当前模型和 Provider 继续由 `session.info` 提供，不从 Agent Catalog 推断。

### 2. 语音回复策略

- 语音策略在后端创建会话时作为 system/developer instruction 注入，不由客户端拼接到普通用户消息。
- 默认策略：回答简洁、自然、口语化；除代码、文件或用户明确要求外避免长篇内容；避免 Markdown 标题、表格和强调符号。
- 代码或长文件保留完整屏幕内容，语音只播报简短结果说明。
- 显示正文与播报正文允许分离：协议优先使用 `speech_text`；旧协议缺失时客户端执行最小 Markdown/TTS 清理。
- TTS 清理负责去除格式符号并跳过代码块、文件路径和长链接，不能只依赖模型遵守提示词。

### 3. 顶部 Agent 区域

- 左侧使用约 40-44vp 的角色头像、紧凑 Agent 名称选择和连接状态，不再显示冗余的 `Agent:` 标签。
- 名称区域限制宽度并对长名称省略；第二行显示当前 `模型 · Provider`。
- 顶部信息表示当前运行配置，消息“过程”表示该轮实际模型、Provider 和总耗时，两者职责不同。
- 第一阶段支持后端头像或名称首字占位；相册选择、上传和跨设备同步后续实现，本阶段仅预留 `avatar_url`。

## 实施顺序

1. [ ] 定义并测试 Agent Catalog 接口及后端配置结构。
2. [ ] 鸿蒙端改为动态 Agent 状态，处理加载、空列表、删除回退和切换。
3. [ ] 重构顶部 Agent 区域，加入头像占位及当前模型/Provider。
4. [ ] 接入后端语音回复策略，不污染用户消息和历史记录。
5. [ ] 增加 `speech_text` 兼容与 TTS Markdown/代码块过滤。
6. [ ] 完成静态检查、自动化测试、HAP 构建和真机验收。

## 验收标准

- 后端增删或重命名 Agent 后，客户端无需升级即可正确刷新。
- Agent 切换、历史记录和语音连接均使用同一个后端 Agent ID。
- 普通语音回答保持简短口语；代码和文件不被长篇朗读，屏幕内容不丢失。
- 顶部 Agent 区域不占满左侧，长名称、模型和 Provider 不与右侧操作重叠。
- 未配置头像时有稳定占位，后续加入相册头像时无需再次修改 Agent 身份协议。
