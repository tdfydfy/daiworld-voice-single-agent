# 真机播放中断与 ASR 分段修复

日期：2026-08-11

## 目标

- 稳定 HarmonyOS 真机耳机播放，避免路由反复切换、PCM 播放器失活后队列搁置，以及由此造成的卡顿、跳字和无故停止。
- 将本地 CoreSpeech 与远端流式 ASR 的服务端短分段合并为一次用户提交，允许自然气口和短暂思考停顿。
- 保持“停止 / stop”“闭麦”和审批、澄清回复等控制语义即时生效。

## 用户原始反馈

> 1、耳机播放时不时终断，有时能够快速重连，体感像是耳机重新接入的状态，左右声道还有些波动，
> 2、有时播放中途卡顿一下，跳过几个字继续朗读；
> 3、有时候直接停止，此时没有任何思考或新消息打扰，若此时再发一条消息，又能在断了的地方重新恢复朗读；
> 二、收音终断：
> 1、有时候说话到一半就中断识别，然后提交任务了；
> 2、分析要么是气口留的时间太短了，只是停顿思考就结束了，但是更多时候是连续对话的中途中断识别，当然只要话不停，就能录入下一段输入，但是这样体感很差，一句话被分成了好几句；
> 一、播放中断：

## 已确认原因

- 通信音频会话每次激活或恢复都会显式设置听筒 / 扬声器，即使耳机已经可用，可能触发系统路由抖动。
- `PcmPlayer` 创建或启动 `AudioRenderer` 失败时静默结束，没有重试；音频会话恢复后也没有唤醒已有播放器，队列可能一直搁置到下一条 PCM 到来。
- ASR 误触发说话暂停后，如果最终只有空文本或纯标点，旧逻辑会丢弃结果但不恢复 TTS，形成“发送下一条消息才继续”的假停止。
- 本地和远端 ASR 都在收到任意 `final` 后立即提交；本地回调的 `isLast` 未参与收句判断，Provider 的自然分段因此直接变成多条 Hermes Prompt。

## 实现范围

- [x] 耳机可用时让 HarmonyOS 管理输出路由，只在没有耳机或明确选择扬声器时应用手机端回退设备。
- [x] 为有待播 PCM 的播放器增加有上限退避，并在通信音频会话恢复后主动恢复 renderer。
- [x] 明确停止时取消播放器恢复定时器，避免旧播放任务复活。
- [x] ASR 空文本 / 纯标点误触发结束时恢复被暂停的播报。
- [x] 为普通 ASR final 增加约 1.1 秒合并窗口，用同一个临时用户气泡累计连续分段。
- [x] 新的 interim / final 到来时刷新收句窗口；控制词和待处理协议回复即时提交。
- [x] ASR 关闭或异常时保留已有的有语义文本并完成一次提交，避免分段丢失。
- [x] 增加 Harmony 静态回归检查，并完成 Node、Python、ArkTS 和签名 HAP 构建验证。

## 真机验收

- 已连接耳机连续播报长回复，确认无重新接入感、左右声道波动、跳字和无故停止。
- 播报期间短暂音频焦点变化后，确认剩余内容能自动继续，不需要发送新消息唤醒。
- 连续说一句带 0.5-1 秒自然停顿的话，只形成一条用户消息；停顿结束后约 1.1 秒内提交。
- 连续说话即使 Provider 给出多个 final，也合并成一条用户消息。
- “停止”“暂停收音”“同意 / 取消”和澄清回复仍能即时执行。
- 真机安装、点击、说话、听感和视觉判断由用户操作。
