# 审批请求语音播报与快速应答

## 目标

- 审批请求不只依赖屏幕弹窗；用户在外放或耳机环境下也能听到风险摘要并完成决定。
- “同意”“取消”等控制词只消费为审批响应，不创建用户消息，不触发新的 Agent 任务。
- 弹窗、语音和 Hermes 状态保持一致，重复或迟到响应不会污染当前对话。

## 当前基础

- Web 已有审批提示播报、`同意/拒绝` 识别和按钮响应的首版路径。
- HarmonyOS 已有审批状态、系统语音输出和同意/拒绝响应路径。
- 本计划补齐词表、取消命名、播放与收音并发边界，以及真机验收。

## 实施顺序

1. [ ] 统一 `approval.request` 的播报摘要和快速应答词表。
2. [ ] Web 保持协议回归，覆盖重复响应、播放中应答和控制词消费。
3. [ ] HarmonyOS 明确外放 / 耳机下的播报、收音和按钮状态。
4. [ ] 完成静态检查、自动化测试、HAP 构建和真机验收。

## 验收标准

- 收到审批请求后，屏幕显示审批详情且自动播报“需要确认”的简短提示。
- 说“同意”或“取消”只发送一次 `approval.respond`，不新增用户消息。
- 语音播报时说出快速应答可以被识别；普通补充语句不会误通过审批。
- 审批已完成后再次点击或再次说控制词不会重复执行或改变历史。
