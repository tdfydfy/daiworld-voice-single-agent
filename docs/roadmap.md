# 项目路线图

更新时间：2026-08-13

## 长期目标

以[HarmonyOS 音频用户旅程](HARMONYOS_AUDIO_USER_JOURNEY.md)为产品北极星，将 HarmonyOS 移动应用交付为连续、可干预、可恢复的单 Agent 语音客户端：用户的有效表达不丢失，Agent 已接受的任务不重复执行，已经产生的回复不无故跳过，亮屏/息屏和前台/后台不改变用户意图。Web Native 在当前版本稳定后暂停新增功能，只保留技术预览、协议验证和必要的稳定性修复。

## 成功基准

- HarmonyOS 真机可稳定循环完成“发起或补充 -> 等待 Agent -> 聆听播报 -> 停止或继续补充”，并在亮屏/息屏、前台/后台、听筒/扬声器/耳机条件下保持相同语义。
- 同一输入最多被 Agent 接受一次；补充内容不丢失；停止任务能清空当前和排队任务；关闭/打开话筒只切换消息路由；退出软件完整释放本地资源。
- 新回复、历史重读和提醒使用唯一可听输出管线；持续采集、ASR 和系统指令使用唯一输入管线；局部故障只恢复对应责任域。
- Agent、模型和 Provider 由服务端受控接口提供，客户端不写死部署拓扑或凭据。
- 审批在对话中保持可见，支持语音播报和“同意 / 取消”快速应答，且默认安全失败。
- Web 与 HarmonyOS 共用正式协议契约；Web 不承担后续产品功能对齐目标。

## 范围边界

- 包含：单 Agent Hermes 会话、动态 Agent Catalog、原生语音输入输出、历史、审批、澄清、附件和移动端交互。
- 暂不包含：主持人多 Agent 编排、客户端维护 Agent 固定清单、Web 新产品功能扩展。

## 关键路径

1. [x] 完成 `1.1.0 安全与连接韧性` 里程碑：Gateway 鉴权/会话重连、协议回归和签名构建；其中 HUKS 令牌存储已因目标真机兼容性在 `1.1.2` 改为应用私有 Preferences。
2. [x] 部署带应用层心跳的 Adapter 并安装 `1.1.1` HAP；用户已确认版本基本可用。
3. [x] 完成第一轮 HarmonyOS 核心语音架构收敛：凭据恢复、公共 TTS 分段和当前/历史消息重读曾通过真机验证；系统语音为主，远端语音为手动辅助。后续息屏回退由第 5 项重新打开，不再沿用本项的旧验收结论作为当前发布依据。
4. [x] 完成核心文件功能拆解，按状态所有权建立 Hermes 运行、ASR 输入、统一音频输出、后台任务和消息过程边界；`SingleAgentController` 已由约 3636 行降至约 1339 行，并通过静态契约和构建回归。
5. [ ] 建立用户旅程的持续运行底座：先用行为测试固定四段循环的不变量，再完成录播专用后台模式切换、首段 ready 门、真实采集健康、有限恢复和统一收句缓冲。
6. [ ] 逐段交付用户旅程：完成发起/补充的精确提交与输入路由、等待 Agent 的确认/恢复、聆听播报的唯一输出队列，以及停止任务、打开/关闭话筒和退出软件的完整语义。
7. [ ] 按完整循环完成自动化与真机验收：亮屏/息屏和前台/后台不另建路径；至少覆盖连续采集、播报中补充、断线恢复、停止任务、退出释放和主要音频路由。
8. [ ] 在核心旅程稳定后验收审批快速应答、连续 ASR 体感和其余交互增强；稳定 Web 技术预览并暂停新增功能。

当前发布边界：`1.2.5` 保留结构拆分、历史按钮重读、公共短句分段、运行身份同步、采集有限恢复和原生设备选择，但撤销真机不可用的 CoreSpeech PCM 接管及录播组合租约。当前恢复 `1.1.2/1.2.1` 已验证过的系统 TTS 内置播放和专用 `AUDIO_PLAYBACK`/`AUDIO_RECORDING` 切换，息屏播放连续性重新进入真机门。后续不再按单个故障横向扩展任务，以四段用户旅程作为范围和验收北极星；当前 P0 从持续运行底座开始，随后逐段交付输入、Agent 状态、播报和干预语义。任务顺序见[当前计划](PLAN.md)，本次方向来源见[用户原文](plans/2026-08-13-user-journey-north-star.md)。
