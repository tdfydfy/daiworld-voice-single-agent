# 项目路线图

更新时间：2026-08-12

## 长期目标

以 HarmonyOS 移动应用作为单 Agent 语音客户端的最终交付面，让用户在手机上持续语音对话、选择服务端动态 Agent、查看过程并安全处理审批。Web Native 在当前版本稳定后暂停新增功能，只保留技术预览、协议验证和必要的稳定性修复。

## 成功基准

- HarmonyOS 真机可稳定完成登录、动态 Agent 选择、Session 创建/恢复、连续 ASR、增量 TTS、打断和后台恢复。
- Agent、模型和 Provider 由服务端受控接口提供，客户端不写死部署拓扑或凭据。
- 审批同时具备可见弹窗、语音播报和“同意 / 取消”快速应答，且默认安全失败。
- Web 与 HarmonyOS 共用正式协议契约；Web 不承担后续产品功能对齐目标。

## 范围边界

- 包含：单 Agent Hermes 会话、动态 Agent Catalog、原生语音输入输出、历史、审批、澄清、附件和移动端交互。
- 暂不包含：主持人多 Agent 编排、客户端维护 Agent 固定清单、Web 新产品功能扩展。

## 关键路径

1. [x] 完成 `1.1.0 安全与连接韧性` 里程碑：Gateway 鉴权/会话重连、协议回归和签名构建；其中 HUKS 令牌存储已因目标真机兼容性在 `1.1.2` 改为应用私有 Preferences。
2. [x] 部署带应用层心跳的 Adapter 并安装 `1.1.1` HAP；用户已确认版本基本可用。
3. [x] 完成第一轮 HarmonyOS 核心语音架构收敛：凭据恢复、公共 TTS 分段和当前/历史消息重读曾通过真机验证；系统语音为主，远端语音为手动辅助。后续息屏回退由第 5 项重新打开，不再沿用本项的旧验收结论作为当前发布依据。
4. [x] 完成核心文件功能拆解，按状态所有权建立 Hermes 运行、ASR 输入、统一音频输出、后台任务和消息过程边界；`SingleAgentController` 已由约 3636 行降至约 1339 行，并通过静态契约和构建回归。
5. [ ] 固化 HarmonyOS 统一录播和控制语义：以[音频用户旅程与业务逻辑](HARMONYOS_AUDIO_USER_JOURNEY.md)约束单一对话循环；输入侧持续采集和ASR，仅切普通/系统指令消息路由；输出侧统一正文、重读和四类提醒；下层使用录播组合持续任务并补齐真实健康恢复。停止任务、退出软件和亮屏/息屏不得产生旁路。
6. [ ] 完成其余语音交互增强验收：连续 ASR 单句合并、系统指令门、停止任务清空队列、退出释放和提醒音仲裁纳入核心音频可靠性；后续再处理审批快速应答及外放/耳机场景。
7. [ ] 稳定 Web 技术预览并暂停新增功能，将后续产品化投入集中到 HarmonyOS。

当前发布边界：`1.2.1` 已完成结构拆分、历史按钮重读、公共短句分段和运行身份同步，但用户再次复现息屏播放中断/卡顿/吞字与录音中断，旧的息屏验收结论已重新打开。当前 P0 是稳定后台音频所有权、真实采集健康和播放完成语义；连续 ASR 体感验收顺延。当前关键路径见[息屏录播可靠性回退与恢复](plans/2026-08-12-screen-off-audio-regression-recovery.md)。

当前执行细节见 [当前计划](plan.md)，当前恢复点见 [项目状态](status.md)。
