## 当前阶段：`1.2.1` 连续 ASR 停顿判定

- 来源：[用户原始任务](plans/2026-08-12-core-file-decomposition-and-screen-off-tts.md)
- 拆解原则：[薄客户端拆解原则](plans/2026-08-12-thin-client-decomposition-principles.md)
- 真机授权：[长期构建部署与简单冒烟授权](plans/2026-08-12-permanent-device-smoke-authorization.md)。本项目后续可直接安装签名 HAP、拉起声明的 Ability，并执行设备/包/进程和简单接口检查；复杂交互、功能判断、语音听感与视觉美感仍由用户验收。
- 目标：保持薄客户端边界，将普通连续 ASR 的收句窗口从 1.1 秒延长到 1.8 秒，减少自然气口和短暂思考造成的过早提交。
- 架构约束：麦克风输入、Agent/Session、音频输出和应用前后台状态正交；Gateway 重连不得重置音频；系统语音是默认主路径，远端语音仅由用户手动选择；思考呼吸音保留循环播放但服从统一输出优先级。
- 方案状态：结构拆解、历史按钮恢复、公共 TTS 分段、运行身份同步和暂停收音均已完成；思考提示音已实现显式生命周期，转入长期观察；当前只开发连续 ASR 停顿判定。
- 简化原则：保留一个面向 UI 的薄控制器，只拆为设置/鉴权、Hermes 运行、语音输入、语音输出、对话状态五个清晰责任域；不引入事件总线、通用依赖注入、重复仓储/用例层或“一方法一模块”。

- [x] [P0/凭据] 可靠恢复访问口令并区分未配置、写盘失败和服务端鉴权失败
  - 方案摘要：目标真机 HUKS AES-GCM 保存后无法回读，按用户决定降级为应用私有 Preferences；写入后同步读回验证，启动时清理不可恢复的旧 HUKS 记录。
  - 已验证：重新保存后真机日志显示 `token save stage=complete`；强制停止并重开后显示 `token load record=present`，应用前台启动且不再进入存储错误状态。
  - 剩余验收：设备重启解锁后重开仍需用户后续观察；服务端 `401/403` 继续独立标记为 `unauthorized`。

- [x] [P0/声音] 验收拆解后的息屏长文播报修复
  - 真机结论：用户确认息屏长文本朗读不再中断或漏字，其他方面未发现问题。
  - 已实施：定位到持续开麦时后台任务始终选择 `AUDIO_RECORDING`；现改为系统 TTS `queued/playing` 期间优先 `AUDIO_PLAYBACK`，播完或用户开口暂停后恢复 `AUDIO_RECORDING`，麦克风采集不停止，并记录后台意图切换日志。
  - 验收条件：亮屏/息屏、开麦/闭麦的长文播放无断连、爆破音、漏段、缺字或重复段；呼吸音在思考期稳定循环，并在 TTS、错误、中断和完成时正确让路/停止。

- [x] [P1/身份] Session 创建、恢复、重连和切换后主动同步 Provider/模型
  - 方案摘要：以 `session.info` 为运行身份权威，并主动加载受控模型目录完成 generic Provider 映射；设置页仅展示共享状态，不再承担刷新职责。
  - 模型目录结论：备用 Provider 的可选模型已通过 Hermes `providers.<provider>.models` 手工声明，并已在 HarmonyOS 真机验证选择和切换生效；客户端不维护模型清单。
  - 审计结论：Session 创建、历史恢复、Gateway 重连和模型切换均汇入同一个身份同步入口；设置页不触发身份刷新。
  - 已修复：切换 Agent 或目录回退时清除上一个 Agent 的模型目录缓存和未确认身份，避免新 Session 暂时返回 `custom` 时误套旧 Agent 的具体 Provider。
  - 状态语义：顶部“在线”表示手机经 Adapter 到当前所选 Hermes Profile 的 Gateway 已 ready 且 Session 已建立；不表示模型供应商当前一定可调用，也不表示 Agent 正在执行任务。后续可将文案收敛为更准确的“已连接”。
  - 真机结论：用户确认启动、新建、历史恢复、Agent/模型切换后的 Provider/模型身份显示通过；模型目录由 Hermes Provider 配置提供。
  - 验收条件：无需进入设置页即可看到已确认的 Provider/模型，重开和恢复 Session 后不长期显示错误的 `custom`。

- [x] [P0/结构] 拆解核心文件功能边界
  - 方案摘要：保留 `SingleAgentController` 作为 UI 命令门面和跨域协调点；小步形成 `AppSettingsStore`、`HermesRuntime`、`VoiceInputCoordinator`、`VoiceOutputCoordinator`、`ConversationState` 五个责任模块。UI 组件拆分放在业务边界稳定后，不做一次性大重写。
  - 验收条件：每个模块有单一可描述职责；控制器只保留编排和状态汇总；新增或修复语音问题可以在单模块内定位并配套静态/单元验证；现有协议、会话连续性和真机行为不回归。
  - 风险：过早按文件切分可能复制状态或引入异步竞态；拆解顺序必须以所有权和事件边界为准。
  - 非目标：不追求理想行数，不为非关键 corner case 新建抽象，不重写 Hermes 协议，不同时改 UI 和音频行为。
  - 候选顺序：先补主流程行为保护并物理拆开音频平台类；再抽语音输出、语音输入、Hermes 运行和对话状态；最后拆 UI 大 Builder。
  - 完成结果：已形成 `AppSettingsStore`、`HermesRuntime`、`VoiceInputCoordinator`、`VoiceOutputCoordinator`、`ConversationState` 五个责任模块，并拆开音频平台类；历史解析归入 `ConversationState`，模型目录/切换与 Gateway 鉴权、目录加载、超时和重连状态归入 `HermesRuntime`。控制器由约 3636 行降至 1339 行。28 个 ETS 文件静态校验、ArkTS 类型检查和签名构建通过。

- [x] [P0/声音] 验收统一分段后的播放中途息屏衔接
  - 已知现象：息屏后开始长文播放正常；亮屏点击历史消息重读后，中途关闭屏幕会跳过一句或半句。日志显示应用没有主动停止或跳段，系统 TTS 仍报告正常完成。
  - 已实施：新消息和历史重读不再维护不同分段模式，两者统一使用首段 20–48 字、后续优先 40–80 字、硬上限 96 字的句边界规则；最终余段同样受上限约束。亮屏/息屏不进入业务分支。
  - 真机结论：用户确认新消息自动播报和历史消息重读在播放途中关闭屏幕均能连续播放，没有再出现中断、漏字或明显衔接问题。
  - 验收条件：新消息和历史重读都能连续播放；任一长段播放中途息屏不再明显跳句、缺半句或重复衔接。
  - 边界：系统 TTS 不提供真实播放进度；若统一短分段后仍明显吞音，再单独验证系统合成 PCM 与应用自管播放，不用屏幕事件猜测进度。

- [x] [P2/后续] 消息按钮重读修复
  - 已知现象：语音说“重读一次”后曾偶发再次发声，但当前客户端没有本地重读控制词，该现象不能证明重读链路成功；消息气泡按钮当前无效。
  - 已实施：按钮绑定确认有效；日志定位到系统重读把首段错误留在队列、却没有启动任何 TTS 的死锁。现改为首段直接启动、其余分段排队，同时保留既有重读状态与清理保护。
  - 真机结论：历史记录重读按钮可点击并有声；代码、链接、文件路径和 `MEDIA:` 过滤规则保持一致。是否新增本地语音重读指令需单独确认。
